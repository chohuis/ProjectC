# 05. UI 체계

주중 관리 화면의 골격·화면 목록·컴포넌트·색 체계를 정한다.
경기 화면(S-M1~M3)은 이 골격을 쓰지 않는다 — [01-gdd.md](01-gdd.md) 11장.

> **확정 경위.** 방향 후보 10안을 4차에 걸쳐 좁혀 **데이터 밀집형(FM 계열)** 으로 결정했다.
> 이유는 세 가지 — 화면이 20개를 넘어도 구조가 안 무너지고, 회원 30명 × 12열이 한 화면에 들어가고,
> 구현 난도가 가장 낮다.

---

## 1. 골격

네 영역으로 고정한다. **모든 화면이 같은 골격을 쓴다.** 바뀌는 것은 본문뿐이다.
타이틀 바와 상태 바는 어떤 화면에서도 사라지지 않는다.

```
┌─────────────────────────────────────────────────────────────────┐
│ 타이틀 바  h28   ◀ ▶  대신동FC › 회원 명단 › 이규민   2029.03 2주차 │
├───────────────┬─────────────────────────────────────────────────┤
│               │ 탭 바     h26   개요 │ 능력 │ 출전 이력 │ 관계 │ 회비  │
│  트리          ├─────────────────────────────────────────────────┤
│  w150~180     │ 요약 스트립  h40   다음 경기 · 참석 · 잔액  (선택)  │
│               ├─────────────────────────────────────────────────┤
│  운영 5       │                                                 │
│  클럽 5       │ 본문       화면마다 다름                          │
│  기록 4       │                                                 │
├───────────────┴─────────────────────────────────────────────────┤
│ 상태 바  h28   회원 12명 · 남은 행동 3 · 인원 2 부족   [ 주 진행 ▶ ] │
└─────────────────────────────────────────────────────────────────┘
```

| 영역 | 치수 | 규칙 |
|---|---|---|
| 타이틀 바 | `h28` 고정 | 뒤로/앞으로 · 경로 · 날짜. **화면 이동 히스토리는 여기서만 관리한다** |
| 트리 | `w150~180` | 3그룹 14항목 고정. 스크롤 없음. 뱃지로 "볼 게 있는 화면" 표시 |
| 탭 바 | `h26` | 화면 안의 관점 전환. **최대 6개.** 넘치면 화면을 쪼갠다 |
| 요약 스트립 | `h40` 선택 | 4~6칸. 그 화면에서 늘 봐야 하는 숫자. 화면마다 내용이 다르다 |
| 본문 | 나머지 | 표가 기본. 상세는 3분할(초상 / 수치 / 경고) |
| 상태 바 | `h28` 고정 | 전역 요약 + **주 진행 버튼.** 주간 루프의 확정 지점은 항상 같은 자리 |

**해상도.** 기준 1920×1080, 최소 지원 1280×720.
트리 폭만 180 → 150으로 줄이고 나머지는 본문이 흡수한다.
낮추지 않는 이유는 GDD 14장과 같다 — 한글 글리프와 표 밀도가 이 장르의 요구다.

## 2. 네비게이션 3단

화면이 늘어나도 구조가 안 무너지는 이유다. **깊이를 3단으로 제한하고 그 이상 파지 않는다.**

| 단 | 수단 | 용량 | 바뀌는 것 |
|---|---|---|---|
| 1단 | 좌측 트리 | 14 (최대 20) | 화면 전체 |
| 2단 | 상단 탭 | 화면당 최대 6 | 본문만. 스트립은 유지 |
| 3단 | 표 행 더블클릭 | — | 상세로 진입. 경로에 한 칸 추가 |

회원 상세에서 또 파고들어야 한다면 그건 탭으로 만든다.
경로가 `클럽 › 회원 명단 › 이규민`보다 길어지지 않는다.

### 2.1 트리 구성

| 그룹 | 항목 | 뱃지 조건 |
|---|---|---|
| 운영 | 이번 주 · 회원 명단 · 라인업 · 일정 · 단톡방 | 명단 = 주의 회원 수 / 단톡방 = 안 읽은 메시지 |
| 클럽 | 재정 · 영입 · 구장 · 규칙 | 재정 = 미납 시 `!` / 영입 = 새 지원자 수 |
| 기록 | 경기 기록 · 상대팀 · 연대기 · 내 정보 | 없음 |

**13항목.** 설정은 트리에 두지 않고 타이틀 바에서 연다.
뱃지는 **0이면 표시하지 않는다.**

## 3. 화면 목록 (E57)

트리 화면 14 + 경기 전체화면 3 + 오버레이 7 = **24개.**
탭까지 세면 실제 구현 단위는 **56개.** (설정을 더하면 25화면 · 57단위)

## 5. 색과 타이포

### 5.1 색은 두 계열로 완전히 분리한다

**크롬색**(배경·패널·보더·선택)은 스킨마다 바뀐다.
**상태색**(좋음·주의·나쁨)은 **스킨과 무관하게 의미가 고정**이다.
이렇게 나눠야 스킨을 갈아도 "빨간 건 나쁜 것"이 안 흔들린다.

| 계열 | 토큰 | 의미 |
|---|---|---|
| 크롬 | `--c-bg` / `panel` / `chrome` | 바탕 3단계 |
| 크롬 | `--c-bd` / `bd2` | 보더 강 / 약 |
| 크롬 | `--c-tx` / `tx2` / `tx3` | 글자 3단계 |
| 크롬 | `--c-sel` / `selTx` | **선택색 — 스킨의 성격을 결정하는 단 하나의 색** |
| 상태 | `--c-ok` | 참석 · 양호 · 수입 |
| 상태 | `--c-warn` | 미정 · 주의 · 경고 누적 |
| 상태 | `--c-bad` | 불참 · 무응답 · 지출 · 이탈 위험 |

**능력 바와 기질 바는 또 다른 색을 쓴다.**
상태색을 쓰면 "기술 62"가 나쁜 값처럼 보인다. 능력은 선택색 계열, 기질은 중립 계열로 간다.

### 5.1.1 팀 색 (S-M2)

경기 화면의 팀 구분은 **세 번째 계열**이다. 크롬색·상태색과 겹치지 않아야 한다.

| 대상 | 색 | 비고 |
|---|---|---|
| 우리 팀 | `#4A7FC4` | 파랑 |
| 상대 | `#BF4238` | 빨강 |
| GK | `#E0C246` | 노랑 — 양팀 공통 |
| 공 | `#F4F1E6` | 흰 원 |
| 볼 소유 | 흰 테두리 | 팀 색 위에 |
| 지시 무시 중 | 선택색 테두리 + `✗` | GDD 11.5 |

### 5.2 타이포 스케일 (1920 기준)

| 역할 | 크기 | 비고 |
|---|---|---|
| 강조 수치 | 32 / 24px | 잔액 · 참석 인원 · 만족도 |
| 화면 제목 | 15px | Bold |
| 표 본문 | 13px | **가장 많이 쓰이는 크기.** 숫자는 `tabular-nums` |
| 표 헤더 · 탭 | 11px | |
| 라벨 · 캡션 | 10px | 자간 +0.16em |

**한글 최소 12px을 지킨다.** 10px 라벨은 한글을 쓰지 않거나 짧은 단어만 쓴다.

## 6. 이벤트 드로어

FM 계열 UI의 유일한 약점이 **"이벤트를 팝업으로 띄울 수밖에 없다"** 는 것이었다.
레트로 픽셀 안(메시지 박스)에서 나온 해법을 이 골격으로 옮긴다 —
**상태 바 위로 드로어가 열린다.**

모달이 아니므로 **뒤의 명단이 그대로 보인다.**
이벤트 대상이 표에서 강조되고 드로어에서 대사와 선택지가 나온다.
**선택지를 고르기 전에 그 회원의 수치를 다시 볼 수 있다** — 이게 모달과의 결정적 차이다.

| 상태 | 높이 | 내용 |
|---|---|---|
| 없음 | `0` | 상태 바만 |
| 알림 | `h30` | 한 줄. 확인만 하면 닫힘 |
| 선택 필요 | `h88` | 구분 · 대사 · 선택지 2~4개. **대상 행이 표에서 강조** |
| 연속 | `h88` | 같은 주에 여럿이면 순차. 우측에 `2 / 5` |

13장 이벤트 시스템의 출력이 전부 이 드로어로 흐른다.

## 7. 스킨

**골격은 하나고 스킨은 변수만 갈아끼운다.**
Godot에서는 `Theme` 리소스 교체로 처리한다 — **스킨을 바꿔도 화면을 다시 만들지 않는다.**

### 7.1 확정

| | 처리 |
|---|---|
| **기본값** | **C 새벽** |
| 설정에서 선택 | **A · B · C · D 전부 지원** (S-15) |

색 토큰만 바꾸면 되므로 4종 지원 비용이 거의 없다.
**단, 상태색(ok/warn/bad)은 스킨마다 재조정한다** — 밝은 바탕과 어두운 바탕에서
같은 빨강이 같은 강도로 읽히지 않는다.

### 7.2 스킨 4종

| ID | 이름 | 성격 | 선택색 |
|---|---|---|---|
