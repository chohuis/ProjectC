검토 1회차에서 탭 57 → 41로 줄었다

열두 화면에서 16탭이 사라졌다. 공통점이 있다 — 전부 "다른 데서 이미 되는 일"이었다. 정렬은 헤더 클릭으로, 필터는 칩으로, 집계는 토글로, 확대는 상세 진입으로 된다. 탭은 다른 질문에 답할 때만 쓴다.

화면을 그려보는 것이 기획을 고쳤다. "이 칸에 무슨 숫자가 들어가지"를 묻자 문서만 읽을 때는 안 보이던 모순 6건이 나왔다 — 기질 6종 오기, 존재하지 않는 행동 개수 제한, 회비 설정 누락, 물려받은 회원 비율 누락, 직책 위임 누락, 용병 참가비 방향 반대.

스킨 4종 — A 클래식 / B 현대 / C 새벽(기본) / D 잔디. 골격은 하나고 색 토큰만 갈아끼운다. 기본값이 C인 이유는 짙은 남색 + 가로등 주황이 조기축구의 시간대이기 때문이다.

9.5보여주지 않는 것을 정하는 일이었다

화면에서 뺀 것이유
명단의 능력 열수치로 줄 세워 베스트11을 짜면 출전 배분 갈등이 죽는다
만족도 숫자얼굴 5단계만. 참을성이 나쁜 쪽을 가린다
효용 값 패스 .72엔진의 속이 드러난다. 개발 전용, 설정에도 노출 안 함
면접 전 능력·기질정보 공개 범위가 가장 강하게 작동하는 화면
라인업 추천추천은 결국 능력순 정렬이다 — 버튼 하나가 갈등을 대신 푼다
그리고 떠난 뒤에 전부 공개한다. 연대기가 마지막 6개월의 출전 · 만족도 하강 곡선 · 내가 만난 횟수 · 그동안 표시되던 얼굴을 나란히 놓는다.

이미 늦었으니까 보여줘도 된다. 그게 아프다. 참을성 보정이 사후에 청구서로 돌아오는 유일한 지점이다.

기록은 줄 세워도 된다. 능력은 내부 평가고 기록은 실제로 일어난 일이다 — 득점왕은 화면에 있어도 되고 기술 62는 없어도 된다.

10.2수치 사슬이 닫혔다

규칙 8종 기준값  →  신뢰 산식  →  수용률 계수
   ✅ 완료           ✅ 완료        ✅ 완료

S-04 전술 화면이 완성됐고, 그게 경기 화면 전체를 확정했다 — 경기 전 브리핑의 수용률 예보, 매치 뷰어의 ✗ 표시, 경기 후 지시 결산이 전부 킥오프의 같은 판정 한 번을 가리킨다.

사슬은 위에서 아래로만 흐르지 않았다. 규칙을 쓰려니 그 아래가 먼저 필요했다 — 벌금은 회비의 분수라 금액 앵커가, 출전 배분 규칙은 쿼터 단위라 4쿼터가, 출전 제재의 무게를 정하려면 출전 만족도 식이 있어야 했다.

값은 초안으로 넣고 구현하면서 튜닝한다. 돌려보기 전에는 맞는지 알 수 없고, 지금 할 일은 구조가 맞는지 확인하는 것이다.

10.4리스크

리스크대응
매치 엔진 튜닝 코드는 몇 주면 돌지만 "축구처럼 보이게" 만드는 데 끝이 없다.
헤드리스 시뮬레이터로 수치를 보면서 하는 것이 유일한 방어
설계가 계속 불어난다 논의할수록 시스템이 는다. 넓게 설계하는 것과 전부 구현하는 것은 다르다 — 기획이 끝난 뒤 구현 범위를 잘라낸다
개인 프로젝트 규모 주 5~10시간이다. 설계한 것을 전부 만들 수는 없다

10.5검증하려는 것

"세 축 사이에서 조율하는 게 재미있는가?"

재미없으면 일찍 멈춘다. 재미있으면 그때부터 진짜 게임을 만든다. 프로토타입으로 먼저 확인한다는 원칙은 유지한다 — 언제·어떤 범위로 할지만 미정이다.
