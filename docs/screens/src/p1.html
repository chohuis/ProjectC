0이 문서를 읽는 법

화면마다 목적 · 진입 경로 · 요약 스트립 · 탭별 상세 · 설계 노트 순으로 적었다. 시안이 있는 화면은 축소 스크린샷을 함께 싣고, 아직 그리지 않은 화면은 사양만 적었다.

0.1각 화면 항목의 뜻

항목내용
목적이 화면이 없으면 무엇을 못 하는가. 한 화면에 하나의 일만 시킨다
진입 / 나가기어디서 들어오고 어디로 빠지는가. 네비게이션 3단 안에 있어야 한다
요약 스트립화면 상단에 늘 떠 있는 숫자 4~6개. 화면마다 다르다
탭보이는 것 / 여기서 하는 결정 / 근거 세 열로 적었다. "여기서 하는 결정"이 비어 있는 탭은 열람 전용이다
설계 노트왜 이렇게 했는지, 무엇을 일부러 넣지 않았는지

0.2스크린샷에 대하여

모든 스크린샷은 기본 스킨 C 새벽으로 렌더했다. 데이터는 같은 세이브의 같은 주(2029년 3월 2주차)로 통일했다 — 화면을 옮겨 다녀도 같은 사람, 같은 숫자가 이어진다. 이규민(28세 · MF · 이탈 위험 5/5)이 여러 화면에 걸쳐 나오는데, 한 사람이 시스템을 통과하는 모습을 보이려는 의도다.

0.3색이 뜻하는 것

색은 세 계열로 완전히 분리되어 있다. 스킨을 바꿔도 상태색의 의미는 안 흔들린다.

계열예규칙
크롬배경 · 패널 · 보더 · 선택색 스킨마다 바뀐다. 선택색이 스킨의 성격을 결정하는 단 하나의 색
상태좋음 · 주의 · 나쁨 스킨과 무관하게 의미 고정. 참석/불참, 수입/지출, 안전/위험
팀우리 파랑 · 상대 빨강 · GK 노랑 경기 화면 전용. 위 둘과 겹치지 않는다
#141C28 배경
#1A2432 패널
#26344A 보더
#D9863C 선택
#79B87E 좋음
#DCAE5E 주의
#D46B58 나쁨
능력 바와 기질 바는 또 다른 색을 쓴다. 상태색을 쓰면 "기술 62"가 나쁜 값처럼 보인다. 능력은 선택색 계열(파랑), 기질은 중립 계열(보라)로 간다.

12개로 전 화면을 만든다. 새 화면을 추가할 때 새 컴포넌트를 만들지 않는 것이 원칙이다.

컴포넌트쓰이는 곳규칙
데이터 표S-01·02·07·11·12 줄무늬 · 열 정렬 · 행 선택 · 더블클릭 드릴다운. 행 높이 15~20px — 30명이 스크롤 없이 들어간다
속성 바S-03 · S-14 라벨 + 바 + 수치. 능력(파랑)과 기질(보라)은 색을 다르게
요약 스트립 셀전 화면작은 라벨 + 큰 값. 4~6개
상태 칩S-03 · S-06회원 상태 태그. 출전 불만 5/5 회비 미납
경고 박스S-03·07·M1좌측 색 스트라이프 + 제목 + 한 줄 설명
진행 바S-07유니폼 적립 같은 목표 대비 진척
폼 스파크S-02 · S-03 ●◐○· 최근 8주 출전을 한 줄로. 추이가 한 칸에 압축된다
트리 뱃지트리숫자 또는 !. 0이면 표시하지 않음
버튼전 화면주요 1개(선택색) · 보조 다수 · 위험(빨강)은 확인 오버레이 동반
3단 세그먼트S-04 전술지시 선택. 3단 고정 — 0~20 스케일을 쓰지 않는다
이벤트 드로어전 화면상태 바 위로 열린다. O-6 면접도 이걸 쓴다
바둑알 + 체력 링S-M2원 + 등번호 + 둘레 게이지. 전부 _draw()

2.2스킨 4종

골격은 하나고 스킨은 색 토큰만 갈아끼운다. Godot에서는 Theme 리소스 교체로 처리한다 — 스킨을 바꿔도 화면을 다시 만들지 않는다.

ID이름선택색성격
A클래식#316AC52000년대 관리 게임. 밝은 시스템 회색, 행 높이 최소
B현대#3D82C4다크 + 넓은 여백. 가독성 최상, 밀도 최저
C새벽 (기본)#D9863C 짙은 남색 + 가로등 주황. 조기축구의 시간대. 밀도는 A와 같고 다른 관리 게임과 겹치지 않는다
D잔디#3B6E3E따뜻한 종이색 + 잔디 초록. 밝은 테마
상태색은 스킨마다 재조정한다. 밝은 바탕과 어두운 바탕에서 같은 빨강이 같은 강도로 읽히지 않는다. A·D에서는 필드 잔디색도 함께 조정한다.
